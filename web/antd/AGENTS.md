# Frontend agent instructions

## Scope

This file applies to `web/antd/` and inherits all repository-wide requirements from the root `AGENTS.md`.

The frontend is part of the same monorepo as the Go backend, framework, and documentation. Never refer to the former standalone `mss-boot-admin-antd` checkout or a personal absolute path.

## Toolchain

- Node.js 22 or newer.
- pnpm 9.15.9 through Corepack or an equivalent installation.
- React, TypeScript, Umi, Ant Design, and Ant Design Pro Components.

## Canonical commands

Run repository-wide workflows from the repository root:

```shell
go run ./cmd/mss doctor
go run ./cmd/mss setup
go run ./cmd/mss verify --changed
```

Run focused frontend checks from `web/antd/`:

```shell
pnpm install --frozen-lockfile
pnpm lint:js
pnpm tsc
pnpm test -- --runInBand
pnpm build:local
```

Do not use `pnpm lint` as a read-only check until its Prettier step stops writing files. Use `lint:js` and `tsc` for non-mutating validation.

## Development server

Prefer the repository process manager once available:

```shell
go run ./cmd/mss dev
go run ./cmd/mss dev status
go run ./cmd/mss dev logs frontend
go run ./cmd/mss dev stop
```

For a focused manual frontend session, run `pnpm start:dev` from this directory and manage the process with the execution environment's normal lifecycle tools. Do not hard-code `setsid`, `/tmp` log files, NVM installation directories, or workstation-specific process commands into product documentation or automation.

The development proxy routes `/admin/` requests to the local backend. Backend APIs use `/admin/api/*`.

## Generated module boundary

- `src/modules/<module>/`, `src/pages/generated/<Entity>/`, `config/routes.generated.ts`, and `src/locales/generated.*.ts` can contain files generated from `modules/<module>/module.yaml`.
- Files with a `Code generated by mss` header must be changed through the source specification or generator template.
- Put custom behavior in explicitly handwritten files without the generated header.
- Generated routes are merged through `config/routes.custom.ts`.
- Generated locale keys are merged through `src/locales/zh-CN/custom.ts` and `src/locales/en-US/custom.ts`.

## Frontend completion rules

A user-facing change must consider:

- loading, empty, error, and permission-denied states;
- desktop and relevant mobile behavior;
- zh-CN and en-US locale keys;
- backend-enforced authorization;
- generated API/client contract drift;
- focused Jest coverage and TypeScript validation.

Do not implement authorization only by hiding buttons. A corresponding backend permission check and negative test are required.
