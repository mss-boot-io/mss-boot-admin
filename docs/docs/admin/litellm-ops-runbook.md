# LiteLLM 运营与闲鱼充值手册

本文面向日常运营人员，覆盖用户/Key 管理、闲鱼订单录入、充值、对账与退款复核。系统中的美元额度是运营记账额度，不等同于真实法币支付凭证。

## 1. 每日开始前

1. 登录运营平台，确认“网关总览”显示 LiteLLM 可达、同步时间正常且没有 `reconcile_required` 订单。
2. 在“用户与额度”同步一次，确认待充值邮箱能精确匹配一个 LiteLLM 用户。不要用昵称或买家闲鱼名猜测账户。
3. 在“商品映射”确认你“我的闲鱼 → 我发布的”商品 ID 已启用，并核对实付人民币与充值美元额度。当前商品 `1083851032724` 可在页面创建映射；最终额度由运营配置决定，不从标题推断。

## 2. 闲鱼成交后的手工流程

闲鱼桌面网页目前无法打开完整“我卖出的”列表，需要在闲鱼 App 的“我的闲鱼 → 我卖出的”核对订单。

1. 让买家在订单备注或聊天中提供已经注册 LiteLLM 的邮箱；不要收集密码或 API Key。
2. 在 App 核对订单号、商品、实付金额和“已付款”状态。
3. 在运营平台“闲鱼订单”点击“录入订单”，填写外部订单号、商品/套餐、用户邮箱、实付金额；系统会生成稳定 payload hash 并检查重复。
4. 点击“验证付款”。首期由运营人员确认；未核实付款、邮箱匹配不唯一或商品映射停用时不可继续。
5. 点击“批准”，复核充值前额度、绝对目标额度和可能受 Key 上限影响的 Key。
6. 点击“执行充值”。页面显示 `executing/applied_unverified` 时不要重复新建订单或再次点击直接充值；等待回读。
7. 订单到 `completed` 后，将结果告知买家。若进入 `reconcile_required`，按第 4 节处理。

## 3. 用户、Key 与模型运营

- 创建/邀请用户时核对邮箱、角色、默认预算与允许模型；停用/删除前确认没有进行中的订单。
- 签发或轮换 Key 后，原始 Key 只展示一次。立即通过安全渠道交付给用户；离开弹窗后无法恢复，只能再次轮换。
- 修改 Key 的 TPM/RPM、预算或模型权限时，先说明影响范围。普通新用户的默认策略由部署配置控制，运营端不要批量追溯覆盖存量用户。
- 模型页只负责查看健康状态和启用/停用。新增模型、供应商凭据、路由和价格配置走受控部署流程，不能粘贴到运营页面或日志。

## 4. 失败、未知结果与对账

- `retryable_failed`：系统已证明远端未写入，修复原因后可重试原订单。
- `applied_unverified`：写请求已返回但缓存/回读尚未确认；等待系统继续回读。
- `reconcile_required`：结果不确定。打开订单查看 before、target_after 和各 Key 子步骤；点击“对账”只做回读与安全收敛，不新建订单。
- `terminal_failed`：数据冲突、用户/映射无效或安全校验失败；修正业务数据后另行审核，不强制跳状态。

严禁为了“快速修复”直接修改 LiteLLM 数据库、重复调用加额接口或删除失败单据。若必须人工处理，记录工单/备注和最终 LiteLLM 回读值。

## 5. 退款

退款订单一律进入 `refund_review`。运营人员同时核对原充值单、当前剩余额度和原单之后的消费：

- 未执行充值：关闭订单即可。
- 已充值但未消费：经审批后执行受控冲正并回读。
- 已部分或全部消费：不要自动扣成负数；按业务规则人工处理，保留审批与说明。

SpendLogs 是只读账目，不得为退款删除或改写历史消费。

## 6. 自动入单的启用条件

当前浏览器登录态不能用作自动化凭据。生产自动入单只允许闲鱼官方开放平台或明确授权 ERP/连接器，并同时满足：

- 独立连接器凭据已存入 Kubernetes Secret，签名、请求时间窗、防重放验证通过；
- 来源被标记为可信，订单状态由可信来源确认“已付款”；
- 外部订单唯一、payload hash 一致；
- 只命中一个启用商品映射和一个 LiteLLM 用户；
- 商品已显式开启 `auto_apply`。

缺少任一条件时只进入人工队列，不自动充值。正式启用前用测试店铺/测试用户完成重复回调、超时、退款与回读异常演练。

## 7. 上线、回滚与凭据

1. 上线前备份运营模块数据库，记录当前镜像摘要；先迁移，再滚动启动后端，最后更新前端。
2. 使用不可变镜像标签或摘要，检查 `/healthz`、`/readyz`、网关健康和页面动作权限。
3. 用临时 LiteLLM 用户创建一笔测试订单，重复提交同一订单两次，确认只加额一次；清理临时数据并保留验收结果。
4. 回滚应用前先判断新状态是否已写入；数据库迁移不可通过覆盖 PVC 回滚。充值单继续保留并对账。
5. LiteLLM master key、连接器密钥、管理员初始密码只存在远端 Secret；不得复制到文档、聊天、构建上下文或日志。

## 8. 自动化接入待办

要从手工切换到自动入单，Owner 仍需取得闲鱼官方开放平台或授权服务商准入与服务端凭据。接入时实现标准连接器适配器即可；订单、幂等、审批、充值和对账主流程保持不变。
