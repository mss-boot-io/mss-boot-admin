# 全部后台管理页面运行时展示配置

:::warning
状态：后继产品合同已定义，实施和验收尚未完成。本文评估基线是分支
`codex/page-presentation-complete-design` 的提交
`1b855d0b71e2884d7b743d49edc73f4dcd853787`。该基线只有 `supplier.list` 与
`user.list` 两个试点，不能表述为“全部后台管理页面已经支持”。本文中的计划测试和浏览器场景
只有在最终未变化的远端 Head 上实际执行后才是证据。

## 产品目标

管理员能够在“页面展示配置”中选择任意已纳入的后台表格管理页，按应用、当前角色或当前用户调整
允许的展示项，发布后无需修改代码、重新构建或重新部署，刷新目标页即可生效。

“全部页面”的验收口径不是所有路由都可以任意编辑，而是：

1. 所有编译路由百分之百进入机器清单；
2. 所有表格型管理页面都有明确稳定的 `pageKey`；
3. 所有纳入页面都有唯一机器源、双端一致定义、真实运行时消费和浏览器证据；
4. 所有不纳入页面都有明确、持久、可审查的排除原因；
5. 任何配置都不能创建业务能力、改变接口、扩大权限或接管敏感流程。

机器事实位于：

- `.mss/features/admin-presentation-all-management-pages.yaml`
- `.mss/admin-presentation-page-inventory.yaml`
- `.mss/schemas/admin-presentation-page-inventory.schema.json`

前置架构和两个试点见[页面展示配置完整设计](/admin/presentation-complete-design)。

## 产品边界

### 可以调整

所有纳入页面都至少允许：

- 中英文页面标题；
- 已注册安全列表列的标题；
- 列的顺序、显示、隐藏和宽度；
- 表格密度；
- 编译合同允许的分页大小；
- 已注册安全搜索项的标题；
- 搜索项顺序、显示、隐藏；
- 搜索区域初始展开或收起。

Supplier 是唯一完整参考，还允许：

- 列表组件、默认排序；
- 表单字段、组件、顺序、跨度和列数；
- 详情字段、组件、顺序、跨度和列数；
- 已注册动作的显示、顺序、位置、文案和确认文案；
- 已审查、强类型、有界的可见条件。

### 不能调整

任何页面都不能通过展示配置创建或修改：

- 数据库表、字段、迁移、模型或实体；
- API、URL、HTTP 方法、请求头、请求体、查询键或编码器；
- 路由、菜单实现、权限、角色、主体、数据范围或工作流；
- React 组件实现、导入路径、远程模块、插件或动作处理器；
- JavaScript、HTML、SQL、模板、表达式或下载代码；
- 未注册字段、数据源、动作、校验器或枚举值；
- 密码、Token、OAuth 凭据、会话凭据、Secret 或未脱敏日志；
- 恢复模式、发布权限或治理控制面自身。

### 明确排除

| 页面或路由 | 原因 |
| --- | --- |
| Workplace | 仪表盘和卡片布局不是当前表格页面合同，需要单独版本设计 |
| 个人中心、个人设置 | 包含个人身份、密码、Token、OAuth、通知和个人主题 |
| 登录、注册、找回密码、OAuth callback | 主体建立之前不能依赖已认证展示配置 |
| 应用配置 | 包含安全、存储、邮件、Secret 生命周期和准入控制 |
| 页面展示配置 | 治理、发布、历史、回滚和恢复必须独立于被治理能力 |
| 403、404、catch-all | 安全兜底不是业务管理页 |
| `/`、`/welcome`、`/analysis` 等重定向 | 不渲染独立管理页面，目标保持编译 |

排除不是遗漏。新需求若要支持 Dashboard、个人页或设置页，必须创建新的页面类型、机器合同、安全
审查和独立验收，不能在当前受限表格合同中顺手放开。

## 敏感页面的有限展示面

“角色、菜单、任务、系统配置、在线会话和日志已纳入”不表示它们的敏感能力可配置。

### 角色

可以调整安全列表列和搜索展示。授权树、权限路径、root/default 角色保护、创建、编辑、删除和授权
动作继续由代码控制。

### 菜单

可以调整已注册列表列和搜索展示。路由、组件路径、权限字符串、HTTP 方法、层级变更、API 绑定和
所有写动作继续由代码控制。

### 岗位

可以调整列表和搜索展示。数据范围是授权语义，不是展示语义，不能通过 profile 修改。

### 任务

可以调整已脱敏列表和搜索展示。provider、endpoint、body、metadata、Python、调度、执行、创建、
编辑和删除都不能进入展示定义、预览数据、日志或诊断。

### 通知

可以调整列表和搜索展示。当前用户数据范围、详情权限、投递和已读写入保持服务端权威。

### 系统配置

只允许已经脱敏的列表元数据。配置 content、Secret 分类、详情、新建、编辑、删除、导入和导出均
保持编译。

### 在线会话

只允许 root 用户看到的安全列表展示。会话标识、原始 Token、撤销、当前会话保护和认证事实均不进入
展示 profile。

### 日志

只允许安全列表和搜索展示。数据源、行范围、过滤编码、脱敏、原始展开、文件选择、截断、导出和
权限保持编译。展示配置不能让浏览器读取另一类日志或任意文件。

## 用户故事

### 展示配置作者

作为配置作者，我能在治理控制台看到全部已注册页面、支持范围、当前定义哈希、启用状态和排除原因，
从而只编辑当前构建真实支持的展示能力。

验收：

- 未注册字段、组件、数据源和动作不会出现在编辑器；
- 受限页面不会出现表单、详情或动作工作区；
- 可视化和 JSON 使用同一草稿，往返不会丢失显式 false、null 继承或条件；
- 草稿可保存，但不合法草稿不能发布。

### 发布者

作为发布者，我能审查应用、角色或用户范围的差异，发布当前有效草稿，并通过历史回滚。

验收：

- 发布必须使用当前 ETag 和幂等键；
- 冲突保留本地草稿并显示服务端当前版本；
- 发布后不可变历史保留；
- 回滚是重新发布历史内容，而不是删除历史；
- 草稿、发布和回滚权限相互独立。

### 后台用户

作为页面用户，我能在刷新后看到已发布展示，同时原有查询、分页、错误、权限和业务操作不回退。

验收：

- 优先级为编译默认值 < 应用 < 当前角色 < 当前用户；
- 浏览器不能指定另一个主体；
- 无配置和所有失败路径都使用完整编译默认值；
- 隐藏按钮不改变后端权限；
- 有效 profile 无需重新构建或部署。

### 平台维护者

作为维护者，我能在新增路由或页面时收到确定性闭包错误，并知道必须补充分类、来源、双端定义、
运行时消费和验收证据。

验收：

- 新增未分类路由使 CI 失败；
- 删除路由后遗留清单使 CI 失败；
- 后端和前端 pageKey 或 hash 不同使构建失败；
- 新生成页面默认为 disabled；
- Thin Host 不复制 Foundation core source。

### 安全审查者

作为安全审查者，我能通过直接 API 正负测试和浏览器行为证明展示配置不扩权、不扩大数据范围、
不暴露敏感数据。

验收：

- 未授权数据源保持 403；
- 未授权动作不会显示，直接调用仍被拒绝；
- profile 不包含权限和主体；
- 审计、日志和诊断不包含 profile 文本、主体标识、业务行、Secret 或敏感原始数据。

### 恢复操作员

作为恢复操作员，我能只移除一个 pageKey 的 active allowlist，或启用全局 recovery，让页面立即回到
编译默认值，同时保留草稿、历史和诊断。

## 运行时行为

每个纳入页面只对同一页面身份发起一次有界有效层读取：

    编译默认值
      < 已发布应用层
      < 已发布当前角色层
      < 已发布当前用户层
      < 可信前端权限交集

页面外壳、认证和业务数据不依赖这个可选请求。以下任何情况都必须整层拒绝：

- pageKey、definitionVersion 或 definitionHash 不匹配；
- 文档解析失败；
- 字段、组件或搜索项不在能力定义中；
- 页面大小不在编译选项中；
- 必填或受保护能力被非法修改；
- 数据库存储失败；
- 请求超时或取消；
- recovery 模式；
- 页面未 allowlist。

整层拒绝不能留下半份标题、半份列或部分搜索项。先保留低层有效配置，最终回到完整编译默认值。
有效层读取不能周期性重试形成请求风暴。

## 治理控制台准入

治理控制台是全部页面配置的入口，必须先于页面扩展通过 Wave 0：

1. 全新数据库执行迁移并创建初始管理员；
2. 登录后打开 `/presentation-config`；
3. capability 响应和空 profile 响应都能解析；
4. 页面显示注册能力或明确空状态，不显示“加载失败”；
5. 不出现无限重试、重复请求风暴、控制台错误或未处理 Promise；
6. 可以完成保存草稿、发布、历史、冲突、回滚和恢复继承；
7. 升级路径数据库重复同样验收；
8. adoption disabled 或 recovery active 时治理仍可使用。

只要这个入口失败，全部页面目标即为阻断，不能用 curl、单元测试或 HTTP 200 代替真实页面验收。

## 页面覆盖状态

机器清单将“代码存在”和“产品已验收”分开：

- `implementationState=planned`：只有目标和来源路径；
- `implementationState=generated`：双端产物已生成；
- `adoptionState=disabled`：能力可治理但不应用；
- `adoptionState=shadow`：解析并观测，不改变页面；
- `adoptionState=active`：仅精确 allowlist 页面应用；
- `acceptanceState=pending`：尚无最终 Head 完整证据；
- `acceptanceState=passed`：该页的合同、权限、fallback、浏览器和 Head 证据完整。

文档、测试名称或待执行命令不能把 pending 改成 passed。

## 产品验收门

### 机器合同

- 页面清单通过严格 JSON Schema；
- page id、pageKey、route id 唯一；
- 所有 route 的 pageIDs 都存在；
- 所有纳入 pageKey 都有唯一来源；
- 所有排除页面都有原因；
- 所有当前编译路由与清单一一闭合。

生成的 Umi 路由配置与 npm 包内的路由注册索引是同一生成路由身份的双投影，二者有序路径集合必须
一致并映射到同一条清单记录，不能把它们重复计算为两个用户页面。

### 生成与一致性

- 每个纳入页面只有一个机器源；
- Go、TypeScript、manifest 和注册表从同一标准化对象生成；
- 后端和前端恰好包含 15 个纳入 pageKey；
- 每个 pageKey 的版本和 hash 相同；
- 任何缺失、重复、手改、旧产物或单边产物都失败。

### 运行时

- 每个纳入页面真实调用共享 runtime；
- 每个排除页面不依赖 presentation endpoint；
- 已发布配置硬刷新可见；
- no-profile 与接入前行为等价；
- 超时、500、坏文档、旧 hash 和 recovery 不阻塞业务页；
- disabled、shadow、not-allowlisted、active、recovery 状态可区分。

### 权限与隐私

- 每页包含直接 API 正向和负向测试；
- 角色、菜单、任务、系统配置、会话和日志包含专项敏感字段排除测试；
- 后端权限和行级范围不因隐藏、显示或重排而改变；
- 诊断和审计不记录 profile 值、主体标识或业务数据。

### 质量

- loading、empty、retryable error、403、冲突、404 等适用状态不回退；
- zh-CN 与 en-US 同步；
- 桌面和移动端均可用；
- 键盘焦点和编辑器错误导航可用；
- 无控制台错误和弃用警告；
- 除故障注入外无失败请求或重试风暴。

### 分发与升级

- 外部 Thin Host 使用固定 Admin Go 与 npm 包；
- 不复制 Foundation core source；
- 生成、安装、lint、测试、构建和代表性浏览器行为通过；
- 升级保留业务自有文件和已有 profile；
- hash 漂移使旧层失效但不删除、不改写、不自动发布。

## 内置浏览器验收剧本

所有关键场景必须使用 Codex 内置浏览器打开真实本地 Admin。Playwright、Vitest、curl 和静态审查只能
补充。

| 场景 | 操作 | 可见结果 |
| --- | --- | --- |
| B01 Fresh DB | 新库迁移、登录、打开治理页 | 能力加载成功，无失败和重试风暴 |
| B02 Empty profiles | 查看无 profile 页面 | 明确空状态，可创建草稿 |
| B03 Draft/publish | 改标题、列、搜索、密度、页大小并发布 | 发布成功，历史增加 |
| B04 Runtime refresh | 打开目标页并硬刷新 | 无部署即可看到新展示 |
| B05 Inheritance | 应用、角色、用户分别覆盖 | 优先级确定，恢复继承正确 |
| B06 Permission | 使用无页面或动作权限用户 | 页面/动作不可用，API 仍拒绝 |
| B07 Disabled/shadow | 切换启动模式 | 页面保持默认，shadow 只观测 |
| B08 Active allowlist | 只 allowlist 一个 pageKey | 只有该页应用，其他页默认 |
| B09 Failure fallback | 注入超时、失败、坏层、旧 hash | 页面按时回退，业务数据可用 |
| B10 Recovery | 启用 recovery | 所有页默认，治理和历史仍可用 |
| B11 Rollback | 回滚历史版本并刷新 | 新发布版本生效，历史不删除 |
| B12 Responsive/locale | 桌面、约 390px、双语 | 内容完整、布局可用、文案同步 |
| B13 Console/network | 检查每个关键状态 | 无意外错误、警告、失败请求 |

对每个纳入 pageKey 至少执行一次黄金路径：

1. 记录编译默认页面；
2. 修改至少一个标题、一个列表项、一个搜索项、密度或页大小；
3. 发布；
4. 菜单导航和直接路由都打开；
5. 硬刷新；
6. 检查可见结果和业务请求形状；
7. 检查权限不变；
8. 回滚并再次硬刷新；
9. 保存截图；
10. 检查控制台和失败请求。

Supplier 还要覆盖表单、详情、动作和条件。其他页面必须证明这些未纳入能力仍保持编译行为。

验收开始和结束都重新读取远端 PR Head。如果 Head 变化，全部浏览器证据立即失效。

## 回退

单页异常：

1. 从 activePages 移除该精确 pageKey；
2. 重启并确认编译默认值；
3. 保留 profile、草稿、历史和诊断；
4. 通过后续 PR 修复并重新执行受影响验收。

多页或存储异常：

1. 启用 startup recovery mode；
2. 确认全部页面使用编译默认值；
3. 确认治理、历史和诊断仍可读；
4. 修复后重新从 disabled 和 shadow 开始。

禁止删除 profile 历史、静默改写旧文档、移动公开 Tag、强推或用本地替换掩盖正式合同缺陷。
