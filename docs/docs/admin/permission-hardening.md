## 目标

Admin 权限链路遵循“后端权威、默认拒绝、最小权限、变更可追踪”四项原则。前端菜单、路由和按钮只负责体验投影，不能替代 API 鉴权。

一次受保护请求按以下顺序处理：

1. JWT 或个人访问令牌只提供用户与角色标识，不提供可信的 `root` 或角色状态。
2. 后端从数据库重新读取当前用户、当前角色、启用状态和 `root` 标志。
3. 角色已变更、用户或角色已禁用、会话归属不一致时返回 `401`。
4. 当前身份有效但缺少 API 策略时返回 `403`。
5. Casbin 策略按数据库中的全局修订号收敛；修订读取或策略重载失败时拒绝授权。

## 管理边界

| 能力 | root | 被授权的非 root 用户 | 普通登录用户 |
| --- | --- | --- | --- |
| 读取被授予的业务页面/API | 允许 | 允许 | 按策略 |
| 修改用户、角色、菜单或 API 权限元数据 | 允许 | 拒绝 | 拒绝 |
| 完整替换角色权限 | 允许 | 拒绝 | 拒绝 |
| 修改部门树或岗位数据范围 | 允许 | 拒绝 | 拒绝 |
| 修改或删除受保护的 root/default 角色 | 拒绝通用 CRUD | 拒绝 | 拒绝 |
| 修改或删除 root 身份用户 | 拒绝通用 CRUD | 拒绝 | 拒绝 |
| 查看在线会话或强制其他会话下线 | 允许 | 拒绝 | 拒绝 |
| 当前会话自行退出 | 允许 | 本人自助能力 | 本人自助能力 |
| 通用文件上传 | 允许 | 需 `storage:upload` | 拒绝 |
| 个人头像上传 | 允许 | 本人自助能力 | 本人自助能力 |
| 读取应用配置中的凭据字段 | 允许 | 需 `app-config:secret-read` | 拒绝 |
| 修改应用配置中的凭据字段 | 允许 | 需 `app-config:secret-write` 和应用配置写权限 | 拒绝 |

非 root 委派管理员不能把自己或其他角色提升到自身权限集合之外。本阶段在可委派权限集合、目标角色层级和自授权约束形成稳定契约前，权限元数据写入统一限制为 root。

root 的既有语义保持不变：当前启用的 root 身份绕过普通 Casbin 规则，前端也始终投影为拥有全部业务能力。唯一例外是系统不变量保护——通用 CRUD 不能删除或降级 root/default 角色及 root 用户，避免误删最后管理入口；这不把 root 纳入普通角色授权。

## 注册与默认角色升级

公开注册和首次 OAuth 登录只有在 `security:registerEnabled` 明确开启时才允许创建账号。系统必须存在且只存在一个已启用、非 root 的默认角色；配置缺失、角色缺失、角色禁用或默认角色重复都会拒绝创建账号。

升级迁移会把历史 `admin` 角色的 `default` 标记移除，并创建独立的最小权限 `user` 默认角色。为避免静默降权或保留公开提权路径，以下情况会中止迁移并要求运维先整理角色数据：

- 存在多个默认角色；
- root+default 角色不是规范的 `admin` 角色；
- 历史 root+default 角色被多个用户共同使用；
- 已有非 root 默认角色处于禁用状态。

迁移不会自动改派任何存量用户，也不会复制 root 权限。失败后数据库事务回滚，修复角色拓扑后可安全重跑。

默认注册角色不再因为 root 新建菜单或权限元数据而获得隐式授权。其 `/welcome` 菜单与监控读取 API 由升级迁移显式、幂等地写入；后续任何能力都必须通过版本化角色授权资源明确授予。

## 角色授权资源

`GET /admin/api/role/authorize/{roleID}` 返回排序后的完整路径集合、十进制 `revision` 和强 `ETag`：

```text
"role-authorization-{roleID}-{revision}"
```

写入使用规范路由 `POST /admin/api/role/authorize/{roleID}`，V6 前端必须发送 `If-Match`。匹配时，菜单、组件、派生 API 规则与角色/全局修订号在同一事务内更新；过期草稿返回 `412` 和当前资源，不覆盖管理员正在编辑的草稿。

`paths: []` 表示原子清空该角色全部授权；缺少 `paths` 或包含禁用、不存在的路径返回 `422`，不会部分保存。缺少 `If-Match` 返回 `428`，弱 ETag 或格式错误返回 `400`，修订号过期返回 `412`；服务层也不提供绕过强前置条件的调用方式。

普通角色只有在完整授权资源已经通过 `paths: []` 清空、且没有任何用户仍引用该角色后才能删除。root 和默认注册角色不能通过通用 CRUD 修改或删除；这避免软删除角色留下可在 ID 复用或审计时重新生效的策略。

## 多实例一致性

角色授权提交后，当前实例必须完成同步策略重载，并在配置 watcher 时发布变更通知。每个实例在授权前比较数据库中的全局权限修订号；即使通知丢失，也会在下一次请求前重新加载。数据库读取、策略重载或通知失败不会返回虚假的成功授权结果。

Casbin 使用并发安全的同步执行器，避免策略重载与请求鉴权之间的数据竞争。数据库修订号是事实源，Redis 或进程内队列不承担最终一致性职责。

生产环境必须启用浏览器会话。V6 浏览器只使用 HttpOnly 会话 Cookie、CSRF 校验与服务端 session；不含 `sid` 的历史浏览器 JWT、历史 `jwt` Cookie 和 URL 查询令牌均不再接受。标准 `Authorization: Bearer` 仅保留给文档化的 API 自动化与个人访问令牌，不是浏览器降级通道。用户/角色禁用、改密和会话撤销都以服务端当前状态立即生效。

## 前端投影

前端仅把 `currentUser.role.root === true` 或权限表中显式的 `true` 视为允许；`false`、缺失键和未加载状态一律拒绝。静态直达路由、动态菜单、欢迎页快捷入口、页面动作和应用设置写入共用该判断规则。

窗口重新获得焦点或重新可见时，前端会节流刷新当前用户与动态菜单。权限失效的直达页面在业务组件发起请求前显示本地化 `403`，认证失效仍走统一的登录清理和跳转流程。

## 审计与存储

审计日志和告警历史是只读证据，通用 CRUD 不提供创建、修改或删除入口。用户安全设置变更与日志导出会留下操作者、路径、结果和耗时；密码、令牌、OAuth 凭证、主题值以及 multipart 文件内容不会写入审计记录。

`POST /admin/api/storage/upload` 不再属于任意登录用户的自助接口。非 root 用户（包括个人访问令牌）必须具有显式的 `storage:upload` API 策略。迁移只创建组件和 API 元数据，不给任何存量角色自动授权。

## 配置凭据边界

应用设置的普通读取和写入权限不再隐含凭据权限。以下三个固定字段单独受保护：

- `email/password`
- `security/githubBrowserSessionClientSecret`
- `security/larkBrowserSessionAppSecret`

非 root 角色只有获得 `app-config:secret-read` 后，应用配置 GET 才返回这些字段；没有读取权限时响应正常，但敏感键被省略。`app-config:secret-write` 允许盲轮换凭据，仍需原有应用配置写权限；包含敏感字段的混合请求会整笔授权、整笔提交，拒绝时不会先写入普通字段。大小写别名、Casbin 故障和策略读取错误都默认拒绝且不返回敏感值。新增组件权限不会继承 `/app-config` 的既有授权，也不会自动授给任何角色。

对象存储凭据已完全移出 AppConfig 凭据面。Storage AppConfig 只允许
`storage/maxSize` 与 `storage/allowedTypes`；历史 provider/credential 行不会投影，
已移除 key 的读写不因 `app-config:secret-read` 或 `app-config:secret-write` 而恢复。
Provider 与 SecretRef 的唯一合法来源是进程启动时的不可变 profile。

历史 `SystemConfig.Content` 是不透明载荷，无法可靠判断其中是否包含密码、令牌或私有端点。因此在拆分为类型化配置资源前，其列表、详情、创建、修改和删除统一只允许当前 root 身份；前端直达路由和操作按钮采用同一边界，后端处理器仍是最终授权点。

## 当前边界与剩余限制

- 浏览器认证协议只支持 V6 会话；退役登录、刷新、OAuth 回调、绑定和 WebSocket 查询令牌路由均未注册。
- 个人访问令牌必须包含当前规范的最小身份标识；不完整的历史令牌需要重新签发。
- 本阶段不完成所有历史业务模型的数据范围接线；数据范围仍必须在后续专门变更中按资源逐项验证。
- 通用上传已具备类型和大小限制及显式权限；按用户字节/数量配额与速率限制仍需后续独立实现。
