# 本地调试合同

:::warning
发布状态：v1.3.2 仍是当前稳定版；v1.3.5 已永久停止并保持不可变部分发布；v1.3.6 已选
为 release candidate，但尚未发布。本页描述 Foundation source-only 调试和候选合同；
公共制品对账前，v1.3.6 不可采用，也不是下游本地启动指引。
:::

## Foundation 源码调试

贡献者从仓库根读取 `.mss/commands.yaml`，按其中声明的工作目录、环境和命令启动后端
与前端。先检查本地工具链、锁和工作树，再执行迁移、启动拓扑并读取结构化状态。不要把
源码入口、工作区替换或本地构建二进制记录成下游发行工具。

首次空库迁移的管理员密码只通过隐藏输入或一次性
`MSS_ADMIN_INITIAL_PASSWORD` 注入迁移进程；重复迁移不再需要。密码不能进入参数、
报告、日志或长期服务环境。

仓库参考拓扑通常使用后端 `8080`、前端 `8001`，但以当前
`.mss/commands.yaml` 为权威，不维护第二套启动脚本。端口冲突时先确认监听者属于当前
项目，不批量终止无关服务。

## 日志与状态

源码调试应分别保留后端、Admin Web、依赖就绪和浏览器证据。排查顺序：

1. 工具链、工作树、版本合同与冻结锁是否一致；
2. 端口监听者是否属于当前项目；
3. 数据库迁移和可选资源是否就绪；
4. 前端代理目标、CORS origin 与 Cookie 设置是否一致；
5. `/healthz`、`/readyz`、登录和权限正反例是否通过；
6. 浏览器控制台和网络请求是否无意外失败。

停止进程时只停止当前项目声明的进程。删除数据库、缓存或生成物不是普通排障步骤，必须
先解析精确目标和恢复影响。

## 未来 Thin Host

未来完整发行会把相同诊断、初始化、开发编排和验证能力放入可核验的 Root 工具，并绑定
同版本 Blueprint 与公共包。v1.3.5 没有这条工具来源链，因此本页不展示其 Thin Host
命令。
