## 目标

:::warning
发布状态：v1.3.2 仍是当前稳定版；v1.3.5 已永久停止并保持不可变部分发布；v1.3.6 已选
为 release candidate，但官方 npmjs 包和完整 Thin Host 路径尚未发布。本页记录 Foundation
源码中的响应式能力与候选合同；公共制品对账前，v1.3.6 不可采用，也不是前端采用指引。
:::

v1.3.6 候选 Admin Web 只组合一个前端应用。桌面和移动端共享同一套业务组件、权限判断、
请求契约和
表单校验，不维护两份页面实现。移动适配解决信息密度、触摸操作和导航可达性，不能改变
后端权限或业务语义。

## 实现原则

1. 使用 Ant Design 6 `Grid.useBreakpoint()` 和语义化布局，不读取浏览器 UA 判断设备。
2. 业务页面只使用 Admin Web 的公开导出和 Ant Design 公共 API；桌面表格与小于
   `md` 的卡片投影必须共享查询、筛选、分页和操作语义，不能导入包内私有路径。
3. 表单、抽屉、确认框和操作菜单复用同一 mutation；移动端只调整排列和触控尺寸。
4. 页面必须显式覆盖 loading、空、错误、403、冲突与保存中状态。
5. 不覆盖 `.ant-*` 内部 DOM；品牌和主题走 token，布局走页面样式或 Tailwind。

## 当前响应式边界

- 用户、角色、菜单、部门、岗位、语言、Option、在线会话等实体页使用共享列表或等价的
  响应式投影。
- 任务、通知和系统配置根据断点调整工具栏、摘要与详情布局。
- 顶栏通知在窄屏使用适合视口的宽度，完整通知中心仍保持可达。
- 详情使用 Drawer/Descriptions；移动端不依赖水平滚动才能看到关键字段或操作。
- 应用设置与个人设置复用同一个主题编辑器，并保持相同字段、继承和重置语义。

## 开发调试

Foundation 源码开发按 `.mss/commands.yaml` 运行前后端与针对性检查；这属于贡献者
合同，不表示 v1.3.5 Release 工具存在。浏览器设备模式只能作为快速检查，发布证据还
必须包含真实 Playwright mobile project 和 Codex 内置浏览器人工验收。

## 验收视口

| 视口 | 目的 |
| --- | --- |
| 375 × 667 | 最小受支持手机宽度、长文案与底部操作 |
| 390 × 844 | 主流手机交互与安全区 |
| 768 × 1024 | 平板断点和表格/卡片切换 |
| 1440 × 900 | 桌面信息密度和固定布局 |

每个关键页面至少验证：

- 无横向页面溢出；
- 主操作、返回、关闭和危险操作可通过键盘与触摸完成；
- 焦点可见，弹层关闭后焦点回到触发器；
- 中文和英文长文案不遮挡状态或操作；
- light、realDark、色弱模式与自定义品牌色均可读；
- 关联字段显示名称而非裸 ID，名称缺失时有明确降级文本；
- 403 与空数据不会被误认为加载失败。

## 发布门禁

开发阶段先做针对性检查，提 PR 前按仓库 `.mss/commands.yaml` 扩大验证。一般源码
`verify` 合同可以继续使用，但不能被解释为 v1.3.5 下游工具命令。体积优化在功能追平
和体验闭环后统一处理，生产构建、运行时依赖契约和控制台零弃用警告始终是发布门禁。
