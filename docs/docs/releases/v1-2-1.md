# v1.2.1 发布合同

当前状态：**component-partial / 先由 v1.2.2 接续，随后由 v1.2.3 完成修复**。
当前稳定版为 [v1.3.2](/releases/v1-3-2)；v1.2.3 仅保留为上一稳定回滚基线。

实际结果：Framework 与 V6 前端已从
`80d2d20f1b44105e18706cfa0deb7f8512966f92` 发布；根标签和 runtime image 已创建，
但根工作流仍上传原始 V6 `dist`，再次因含 `:` 的路径失败，最终平台 ZIP 和根 GitHub
Release 未发布。所有 v1.2.1 公开引用保持不可变；当时的完整前向修复见
[v1.2.3 发布合同](/releases/v1-2-3)。

v1.2.1 是 v1.2.0 不完整同步列车的前向修复版本。根仓库、可复用 Framework 和唯一的
Ant Design V6 前端必须来自同一个已合并到 `origin/main` 的新精确提交：

| 组件 | 版本与标签 | 前置条件 |
| --- | --- | --- |
| Framework | `mss-boot/v1.2.1` | 完整 `GOWORK=off` 测试与 `pre-framework` 授权 |
| Admin V6 | `web/antd-v6/v1.2.1` | 集中前端门禁、精确 SHA 浏览器证据、便携制品与同提交镜像 |
| 根发行版 | `v1.2.1` | Framework 外部解析成功与独立 `pre-root` 授权 |

任何本地运行、topic branch 提交、旧候选提交或未合并 PR 的结果都只是预备证据，不能
创建标签、package、镜像或 GitHub Release。

## v1.2.0 不完整列车

v1.2.0 的已有公开状态必须保留为不可变审计事实：

- `mss-boot/v1.2.0` 已从
  `c0b4b4d7888a67931951f0b40198d98614e979af` 成功发布并通过仓库外
  `GOWORK=off` 代理解析；
- `web/antd-v6/v1.2.0` 标签指向同一提交，发布工作流的源码、策略、readiness、依赖、
  测试、Chromium E2E、release build、制品身份和 production smoke 均通过；
- 该工作流随后在上传原始 `dist` 树时遇到含 `:` 的静态路由文件名，制品服务拒绝该
  跨平台不兼容路径；V6 构建制品、镜像与 GitHub Release 均未发布；
- 根 `v1.2.0` 标签从未创建。

禁止删除、移动、复用或补发上述标签。v1.2.1 必须从修复后、重新评审并合入 `main` 的
新提交完成全部同步发布。

## 修复范围

V6 工作流仍在发布构建中生成 `dist-v6.tar.gz`，但制品上传只接收以下三个便携文件：

- `web/antd-v6/dist-v6.tar.gz`
- `web/antd-v6/FRONTEND-V6-BUILD-INFO`
- `web/antd-v6/SHA256SUMS.frontend-v6`

原始 `dist` 目录不再交给制品服务遍历。静态工作流回归测试固定该清单，并继续要求
GitHub Release 发布前验证归档校验和。

除这项发布修复外，v1.2.1 保留 v1.2.0 的产品、Framework、数据库和兼容性边界：

- `web/antd-v6` 是唯一 Admin 浏览器应用、生成目标和发布命名空间；
- 浏览器继续强制使用 HttpOnly 会话、CSRF 和一次性 WebSocket ticket；
- Framework 的 Delete 事务边界、固定错误映射、常量时间 scrypt 校验与非可逆
  SecretRef 指纹保持源码兼容；
- ObjectStore/RustFS 成熟度仍为独立可选工作，不因本次发布自动晋级。

## 数据库与 API 注册表

从现有安装升级前必须备份数据库。v1.2.1 延续以下前向迁移边界：

- `20260815120000_language_integrity`
- `20260815121000_language_management_permissions`
- `20260815130000_option_integrity`
- `20260815131000_option_management_permissions`
- `20260816120000_hide_example_supplier_menu`
- `20260816163000_account_reauthentication`
- `20260817120000_retire_example_supplier_roles`
- `20260817170000_retire_v5_browser_config`

迁移后必须从 `admin` 执行一次实际路由同步：

```shell
STAGE=local go run . server -a
```

该命令同步已挂载路由并正常退出，随后才启动长期后端服务。仅有 `/healthz` 或前端页面
可访问不代表权限数据就绪；“权限管理 → 菜单管理 → 绑定 API”必须出现非空可选 API。
旧候选提交曾得到 139 条唯一 API，只是历史证据，必须在新的 v1.2.1 冻结提交上重新验证。

## 兼容性边界

- 不支持 V5 前端与旧浏览器 token/cookie/WebSocket 协议；后端与 V6 前端必须成对部署。
- 数据迁移是前向的；旧二进制不保证能读取已升级数据库。
- `admin/go.mod` 在发布提交上必须依赖 `mss-boot v1.2.1`；开发期本地 replace 不能作为
  外部可解析证明。
- `.mss/project.yaml` 与 `.mss/lock.yaml` 保留真实开发快照身份，不为公开版本号人工改写。

## 资格门禁

结构化入口为 `.mss/features/foundation-v1-2-1-release.yaml`，资格清单只选择该 Feature；
v1.2.0 Feature 作为不完整列车证据显式 carry-forward。

1. checkpoint：严格 doctor、发布工具测试、Feature 校验、三个组件 tag namespace 校验。
2. feature-freeze：根与 Admin Go 测试、Framework `GOWORK=off`、V6 集中门禁和文档构建。
3. 精确 SHA 人工证据：Codex 内置浏览器产品验收、三数据库 fresh/upgrade/API 注册表验证、
   外部 Blueprint 升级演练。
4. `pre-framework`：选择成功的独立 readiness run，授权 Framework 与 V6 写入。
5. 外部解析：在仓库外使用纯代理和 `GOWORK=off` 解析 `mss-boot@v1.2.1`，记录 checksum。
6. `pre-root`：选择另一个成功 readiness run，授权根发行版写入。
7. 发布后：核对 tags、Releases、archives、checksums、images、安装、迁移、API 注册表和恢复。

任何实现或发布契约变更都会产生新候选提交，并使受影响的旧证据失效。

## 发布顺序

1. 通过 PR 将本次修复合并到 `main`，重新获取远端并确认 tracked worktree 干净。
2. 冻结一个完整 SHA，执行 feature-freeze，不授予发布权。
3. 完成同 SHA 浏览器、三数据库/API 注册表与 Blueprint 证据，解决所有 required blocker。
4. 执行并选择 `pre-framework` 权威 run。
5. 发布 `mss-boot/v1.2.1`，在外部临时模块验证纯代理解析与 checksum。
6. 发布同 SHA 的 `web/antd-v6/v1.2.1`、便携制品和匹配镜像，并核对 GitHub Release。
7. 执行并选择独立的 `pre-root` 权威 run，再发布 `v1.2.1`。
8. 完成发布后对账并关闭 evidence issue。

某一步失败时立即停止后续组件。已经创建的 v1.2.0 或 v1.2.1 标签一律不能移动或复用；
若修复需要代码变更，必须再次提高版本并从新 PR、新 `main` 提交重新资格化。

## 回滚

发布前必须创建并验证数据库恢复点。部署失败时：

1. 停止继续发布或扩散流量；
2. 恢复升级前数据库备份；
3. 部署上一组已资格化的 V6 后端与前端；
4. 验证登录、菜单、API 绑定、权限负例、会话与核心写入；
5. 保留失败提交、日志摘要和证据链接，修复后选择新 SHA 重跑受影响门禁。

不能通过恢复 V5、移动标签、对生产库执行临时 down migration 或绕过 readiness 来回滚。
