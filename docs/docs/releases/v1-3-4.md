# v1.3.4 发布、安装、升级与回滚

v1.3.4 是 v1.3.3 组件部分发布后的协调补丁列车。它保留已经公开的 v1.3.3
组件引用不变，从一个新的 merged-main 精确提交重新发布完整 Admin Distribution。
公开可用性以 [GitHub Release](https://github.com/mss-boot-io/mss-boot-admin/releases/tag/v1.3.4)
以及 Go 代理、npmjs、镜像和 Docs 的公共对账全部完成为准；不得从本文推断尚未发生的
发布已经完成。

:::warning
不要把 `mss-boot/v1.3.3`、`admin/v1.3.3` 或 `web/antd-v6/v1.3.3` 与其他版本
拼装使用。v1.3.3 没有 Root 工具 Release、Docs Release 或 npmjs 包，是不可复用的
[组件部分发布历史](/releases/archive/v1-3-3)。新项目和升级统一使用 v1.3.4。
:::

## 修复范围

v1.3.3 的 Root 前公共 Thin Host 门禁证明：Go 在打包仓库子目录 Module 时，如果模块
目录没有自己的 `LICENSE`，会把仓库根 `LICENSE` 纳入规范 Module ZIP。旧候选构造没有
复现该行为，因而生成的 Thin Host `go.sum` 与公共 `admin@v1.3.3` 不一致。

v1.3.4 在任何组件 Tag 前完成以下修复与资格验证：

- Framework/Admin 候选和所有独立 file proxy 都复现 Go 的根 `LICENSE` 继承语义；
- 候选构造发现根 `LICENSE` 未提交漂移时失败关闭，模块自有 `LICENSE` 仍优先；
- Thin Host 模板记录最终 Admin 与 Framework 的规范 Module Sum 和 GoModSum；
- Framework、Admin 的公共下载探针同时核对版本、提交、Module Sum 和 GoModSum；
- Root 前使用 Release 构建工具从空目录生成 Thin Host，并以 `GOWORK=off`、无本地
  `replace` 的方式下载、测试、构建和运行。

本补丁不移动或覆盖任何 v1.3.3 Tag、Release 或公共 Module，也不改变数据库 Schema、
HTTP API、认证、授权或迁移顺序。

## Root 工具资产

Root Release 为 Linux、macOS、Windows 的 amd64/arm64 提供：

- `mss-tools-v1.3.4-{linux|darwin}-{amd64|arm64}.tar.gz`；
- 对应 Windows ZIP；
- `install-mss.sh` 与 `install-mss.ps1`；
- `SHA256SUMS.tools-v1.3.4`；
- 来源与构建证明。

归档根目录只包含 `mss`、`mss-mcp`、`BUILD-INFO` 和 `LICENSE`。安装器先校验摘要
再替换目标文件，不使用 `sudo`、不修改 shell profile。两个二进制必须报告相同版本、
提交和构建时间。

## 安装与创建

Linux 或 macOS：

```sh
curl -fsSLO https://github.com/mss-boot-io/mss-boot-admin/releases/download/v1.3.4/install-mss.sh
bash ./install-mss.sh --version v1.3.4 --install-dir "$HOME/.local/bin"
export PATH="$HOME/.local/bin:$PATH"
mss --version
mss-mcp --version
```

Windows PowerShell：

```powershell
Invoke-WebRequest https://github.com/mss-boot-io/mss-boot-admin/releases/download/v1.3.4/install-mss.ps1 -OutFile install-mss.ps1
& .\install-mss.ps1 -Version v1.3.4 -InstallDir "$HOME\.local\bin"
$env:Path = "$HOME\.local\bin;$env:Path"
mss --version
mss-mcp --version
```

从空目录创建 Thin Host：

```sh
mss new app my-admin \
  --module github.com/example/my-admin \
  --destination ./my-admin \
  --write \
  --git-init
cd my-admin
mss doctor --strict
mss setup
mss dev
```

生成结果精确导入 `admin@v1.3.4`、`mss-boot@v1.3.4` 和
`@mss-boot-io/admin-web@1.3.4`，并保留 Blueprint manifest、锁文件、业务所有权
seam、验证入口和 CI 合同。普通采用者不需要 Foundation 源码目录。

第一次交互式 `mss setup` 通过隐藏提示读取初始管理员密码；非交互环境只在 setup
进程中注入一次性 `MSS_ADMIN_INITIAL_PASSWORD`。密码不得进入命令参数、报告、生成文件
或长期服务环境。

完整前置条件、开发命令和故障排查见[快速开始](/getting-started)、
[工具说明](/getting-started/tooling)和[包与导入边界](/getting-started/packages)。

## 升级

先安装目标 v1.3.4 工具，确认 `mss --version` 与 `mss-mcp --version` 同源，并备份
代码、配置、数据库和业务数据。只有保留 `.mss/blueprint-manifest.json` 的 Blueprint
Thin Host 才能使用三方升级；手工拼装或丢失基线的仓库必须先在新目录生成 v1.3.4
基线，再迁入业务所有文件。

```sh
mss upgrade admin v1.3.4
mss upgrade admin v1.3.4 --apply --yes
mss doctor --strict
mss verify --all
mss upgrade admin v1.3.4
```

第一次计划只读；应用只更新受管文件并保留业务和未知文件；快照最后写入。第二次计划
必须没有 create、update、delete 或 conflict。数据库变化仍需独立备份、迁移和恢复演练。

## 发布顺序与资格

```text
merged main
  -> Framework
  -> Admin
  -> Admin Web candidate / image / GitHub Release
  -> protected Root tag promotion
  -> Root tools / image / GitHub Release
  -> Docs
  -> official npmjs
  -> public reconciliation
```

每个阶段都重新验证精确提交和全部前置证据。最终使用方资格从空目录和 Release-built
工具开始，不允许 Git checkout、Foundation 源码、本地 Go replacement、本地 npm
tarball 或手写锁文件，并覆盖：

1. 工具摘要、版本、提交和归档边界；
2. 公共 Go Module 与 npmjs 匿名解析；
3. `doctor --strict`、`setup`、`dev`、`verify --all`；
4. Thin Host 后端与前端测试、构建和运行；
5. 手写模块、权限、路由、本地化与五个业务 seam 的升级保留；
6. 匿名 401、受限用户 403、授权 root 200 和内置浏览器关键流程；
7. Admin core 与业务 UI/server 路径冲突失败关闭。

## 回滚与修复

- 发布前缺陷：通过后续 PR 修复，选择新的 merged-main 提交并重跑受影响阶段；
- 发布后缺陷：保持 v1.3.4 ref 与资产不变，使用更高补丁版本；
- 下游回退：恢复匹配版本的代码、配置、锁、数据库快照和业务数据；
- 禁止移动 Tag、重写 Release、覆盖 npm 版本或替换镜像 digest。

发布完成后，[mss-shop](/getting-started/mss-shop) 从公共 v1.3.4 工具和包生成独立基线，
再作为通用单租户商城管理系统的 package-first 采用者范本。
