## 两个阻断根因

### Root image preview

被复用的 container workflow 用 `github.event_name == 'workflow_call'` 判断 preview 模式，
但可复用 workflow 保留调用方的事件上下文。调用方是手工 `workflow_dispatch`，所以
多架构构建、Root OCI 校验、暂存与 artifact 上传都被跳过。preview 整体仍显示成功，
正式 Root container 运行随后才发现制品缺失。

后续版本必须由调用方显式传入并校验布尔 `release_preview`，而且正式 Tag 前必须检查
preview 的 Root image artifact 清单。

### npm Trusted Publishing

npm workflow 已正确申请 `id-token: write`，使用支持 Trusted Publishing 的 npm CLI，
并在 `npm publish --provenance` 前移除 `NPM_TOKEN` 与 `NODE_AUTH_TOKEN`。失败不是应恢复
长期令牌的信号，而是 npm Trusted Publisher 仍绑定已退役的 `release-v6` 环境，和
workflow 实际使用的 `npm-auto` 不匹配。

未来候选只能把 npm package `@mss-boot-io/admin-web` 精确绑定到组织
`mss-boot-io`、仓库 `mss-boot-admin`、workflow 文件名 `npm-release.yml` 与环境
`npm-auto`。不得创建仓库、组织或环境级 npm 发布令牌作为回退。

## 源码能力与采用边界

该提交包含 package-first Thin Host、演示配置管理、加法迁移、后端权限、不可变历史、
冲突控制、恢复模式和安全 bootstrap 等源码能力。源码存在不等于协调发行完成：缺失官方
npm 包和 Root 镜像后，空目录创建、安装、升级、部署与匹配回退链路都无法获得完整公共
制品证明。

已有采用者继续使用完整匹配的 v1.3.2 Admin、Framework、前端、配置与冻结锁。不能把
v1.3.6 后端组件与 v1.3.2 前端、v1.3.7 修复源码或任何本地替换混用。

## 永久停止规则

- 不 rerun 或手工补发 v1.3.6 npm、Root image 或 Docs；
- 不删除、移动、重建或复用 Root 与组件 Tag、Release、包、镜像和校验和；
- 不恢复 `NPM_TOKEN` 或 `NODE_AUTH_TOKEN`；
- 不把 v1.3.6 标记为 stable、latest、recommended 或可采用；
- 所有源码修复通过新 PR、新 merged-main 提交和新未使用版本重新资格验证。

公共 Docs 站仍是独立发布面。本源码页合并后只代表 source-updated；在新的 Docs Tag、
workflow、Release 与 `/release.json` 对账完成前，生产站点仍是 deployment-pending，不能
声称 v1.3.6 文档曾经发布。
