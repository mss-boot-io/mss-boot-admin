# v1.3.6 发布候选说明

v1.3.6 是用于完成 package-first Admin Distribution 的全新候选身份。它不是 v1.3.5
的补发或续发，也不会移动、删除或覆盖任何 v1.3.5 标签、Release、包、镜像或代理记录。

:::warning
本页描述候选合同，**不代表 v1.3.6 已发布或已经成为稳定版**，也不提供下载、安装、创建或
升级命令。当前稳定版与生产回退基线仍是 v1.3.2。只有 Root、Framework、Admin、Admin Web、
工具、npmjs、镜像和 Release 全部公开对账，并在后续独立 Docs 发布完成后，文档才能把
v1.3.6 标为稳定版。
:::

## Package-first 工具与 Thin Host

候选 Root 工具面同时交付 `mss` 与 `mss-mcp` 的 Linux、macOS、Windows amd64/arm64
归档。每个归档只包含两个公共二进制、`BUILD-INFO` 与 `LICENSE`，并绑定版本、源提交、
归档边界和不可变摘要；Shell 与 PowerShell 安装器在写入前验证这些身份。

`mss` 内嵌同版本 Blueprint，使外部使用方能从空目录完成新建、设置、开发编排、验证和三方升级，
并精确依赖 Admin、Framework 与 `@mss-boot-io/admin-web`。Thin Host 只保留组合胶水、机器合同
和业务所有代码，不复制 Foundation 后端、Framework、完整前端、文档或发布流水线。三方升级只
修改受 Blueprint 管理的文件，未知文件与业务后端模块、前端路由、页面、语言包和配置必须保留。

候选和发布后验收都必须在仓库外的空目录执行，并拒绝 Git checkout、本地 Go `replace`、本地 npm
tarball、复制的 Foundation 源码、手写锁文件或混合版本。正式制品未公开前，本节只描述合同，
不能作为可执行快速开始。

## 展示配置：数据边界与默认行为

v1.3.6 候选包含受治理的页面展示配置控制台和后端发布流程。展示文档只能对编译进应用的页面、字段、
数据源、组件和动作标识设置有界标量，例如文案、可见性、顺序、宽度、布局、密度和动作位置。它不能
携带 JavaScript、HTML、SQL、URL、HTTP 方法或请求头、权限、动态导入、可执行组件、运行时模型、
虚拟 CRUD 或浏览器代码生成。

生产能力注册表在这个候选中仍故意为空，因此升级后不会有业务页面采用数据库展示层，现有页面继续使用
编译默认值。控制台本身是静态编译且不可被展示配置控制；空注册表也不能隐藏恢复模式提示、已存聚合或
不可变历史。

迁移新增两张表，不修改已有业务表或配置行：

| 表 | 用途与约束 |
| --- | --- |
| `mss_boot_presentation_profiles` | 可变草稿聚合；以范围、主体和页面键唯一，使用正数聚合版本和强 ETag 防止陈旧覆盖 |
| `mss_boot_presentation_revisions` | 追加式不可变历史；版本号和幂等键在聚合内唯一，回退通过发布一条新修订实现 |

每次发布和回退都在事务内重新核对能力定义哈希，原始幂等键只保存哈希。通用审计正文不记录展示文档、
本地化文案、条件值、原始主体标识或原始幂等键；只记录有界的动作、操作者、聚合、修订、结果和原因。

## 权限与部署顺序

展示管理使用四项互不隐含的后端权限：

| 权限 | 能力 |
| --- | --- |
| `presentation:read` | 查看能力、聚合、历史、恢复状态和执行只读校验 |
| `presentation:draft-write` | 新建或替换草稿 |
| `presentation:publish` | 发布当前有效草稿 |
| `presentation:rollback` | 把历史修订重新发布为新修订 |

迁移建立 `/presentation-config` 菜单、三个动作节点和十个 API 权限节点，但不会给已有普通角色自动
授予兼容访问。前端按钮隐藏或禁用只改善体验，所有读取、草稿、发布和回退仍由后端 RBAC 独立执行
正反向检查。

部署必须使用同一套不可变 v1.3.6 Thin Host 后端镜像和配置，并严格按以下阶段执行：

1. 先运行一次 `migrate` 初始化/升级任务，完成数据库结构和迁移记录；
2. 再运行一次 `server -a`，同步路由、菜单和 Casbin 权限拓扑；
3. 两者成功后才启动长期 `server`，随后验证菜单、四项权限、普通角色 403、显式授权角色和恢复状态。

`migrate` 已移除并拒绝历史 `--password` 与 `-p` 参数，也没有默认管理员密码。交互式 `mss setup`
通过无回显输入读取首次管理员密码；非交互自动化只能把 `MSS_ADMIN_INITIAL_PASSWORD` 注入一次初始化
任务。同步任务和长期服务不得继承该值，已初始化数据库也不能重新创建管理员。

## 迁移兼容与匹配回退

升级前必须备份并实际演练 v1.3.2 数据库、配置、Thin Host 冻结锁、Admin 后端和 Admin Web
制品的灾难恢复。必须记录数据库备份时间，并预先确定在整库恢复前如何导出和独立保全仍可读取的
备份点后审计数据与业务数据。v1.3.6 是协调发行，不能只回退后端、只回退前端或混用组件补丁版本。

发生错误配置、定义漂移或展示存储故障时，先在启动配置中启用：

```yaml
presentation:
  recoveryMode: true
```

滚动启动后确认所有有效层读取都返回恢复状态、业务页面使用编译默认值。正常二进制回退只回退彼此
匹配的 v1.3.2 Admin、Admin Web、配置和冻结锁；不得恢复数据库备份，必须原地保留当前数据库及其
前向兼容的结构和数据。`recoveryMode` 不存数据库、没有 Admin 写接口，也不删除草稿或历史。回退
不得执行破坏性 down migration；两张新增表、不可变修订、权限元数据、审计证据和业务写入继续保留，
便于调查与后续前向修复。

整库备份恢复只能用于灾难恢复，并会丢失数据库备份时间点之后的全部写入。执行恢复前，只要当前存储
仍可读取，就必须先把备份点后的审计数据和业务数据导出到目标数据库之外并完成保全，再恢复匹配的
v1.3.2 数据库备份并执行数据差异对账；不得把这种有损恢复描述为普通版本回退。

## mss-shop 与完成条件

`mss-shop` 尚未获得 v1.3.6 正式公共验收，不能被描述为已完成范本或稳定采用证据。只有在公共 ledger
对账 Root、组件 Release、Go Module、npmjs、工具摘要、镜像 digest 和安装器成功之后，才开始用
真实公共 v1.3.6 制品建立独立的通用单租户仓库，并完成后端、前端、权限正反例、迁移、升级保留和
内置浏览器验收。

在此之前，v1.3.2 仍是唯一稳定基线，[v1.3.5](/releases/v1-3-5) 仍只是不可变部分发布记录。
