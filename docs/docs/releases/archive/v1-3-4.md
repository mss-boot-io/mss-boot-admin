# v1.3.4 组件部分发布记录（不可复用）

> 历史版本：本页只保留不可变发布与失败证据，不用于新项目。当前稳定版是 v1.3.7；
> v1.3.5 与 v1.3.6 已永久停止且只保留不可变的部分发布证据。安装、创建或升级从
> [v1.3.7 快速开始](/getting-started)进入；Docs 网站可通过 `docs/v*` 独立异步发布，
> 其状态不影响组件、稳定别名或采用。

统一修复由 [v1.3.5](/releases/v1-3-5) 承接。
:::

`d9b210d6672800f84f6403496a3ae871fb2aea9f`：

| --- | --- |
| Framework | `mss-boot/v1.3.4` Tag 与 GitHub Release 已发布 |
| Admin | `admin/v1.3.4` Tag 与 GitHub Release 已发布 |
| Admin Web | `web/antd-v6/v1.3.4` Tag 与 GitHub Release 已发布 |
| Root | `v1.3.4` Tag、工具资产与 GitHub Release 未发布 |
| Docs | `docs/v1.3.4` Tag 与 GitHub Release 未发布 |

这意味着只看到 Go Module 或 Admin Web 组件 Release，不能证明完整发行可供采用者安装。
Root 工具、Docs 与 npmjs 缺失时，也不存在受支持的 package-first 新建或升级路径。

## Root 前失败边界

Root 前的外部使用方资格验证从候选 Admin Web 元数据生成 Thin Host。生成锁文件时，
`dist.tarball` 下载地址没有被保留，pnpm 的 frozen-lockfile 解析因而推导出无效的
registry 地址并失败关闭。这个失败证明：

- 完整 npm 元数据必须同时保留版本、integrity 与 tarball URL；
- Thin Host 冻结锁必须从候选 tarball 的真实元数据生成，不能手工补写；
- Root、Docs 与 npmjs 不能绕过外部使用方资格验证单独补发；
- 已公开组件的 Tag、Release 和校验和不能移动或覆盖。

修复随后通过 merged-main 提交
`99a4f1ad157b934841786be031e7c55b8e25f5b5` 合入，但该提交不会改变任何已经发布的
v1.3.4 字节或身份。修复与完整发布资格统一进入新补丁列车。

## 与更早部分列车的关系

v1.3.4 已包含对 Go 子目录 Module 继承仓库根 `LICENSE` 校验和语义的修复，因此三个
已发布组件仍是有效的不可变历史证据；它们只是不能组合成完整发行。更早的部分发布结果
分别保留在 [v1.3.3](/releases/archive/v1-3-3)、
[v1.3.1](/releases/archive/v1-3-1) 与 [v1.3.0](/releases/archive/v1-3-0) 页面。

## 使用与恢复边界

- 不要以 v1.3.4 的组件 Tag、分支、PR 提交、本地 `replace` 或私有 tarball 创建下游基线；
- 已经尝试拼装的仓库应保留业务文件，并迁入一个由完整公开发行工具重新生成的空目录基线；
- 在 v1.3.5 完成公共对账前，采用者继续使用发布策略声明的当前稳定与回滚基线；
- 后续完整发行不得重用 v1.3.4 的任何 Tag、Release、npm 版本或镜像摘要。

当前候选的安装、升级与发布门禁见
[v1.3.5 发布合同](/releases/v1-3-5)。
