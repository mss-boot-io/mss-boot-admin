# v1.2.3 发布合同

> 历史版本：本页仅保留不可变发布、升级与恢复证据，不用于新项目。当前稳定版是 v1.3.7；v1.3.5 与 v1.3.6 已永久停止且只保留不可变的部分发布证据。安装、创建或升级从 [v1.3.7 快速开始](/getting-started)进入；Docs 网站可通过 `docs/v*` 独立异步发布，其状态不影响组件、稳定别名或采用。

历史状态：**v1.2.3 已发布；随后 [v1.3.2](/releases/archive/v1-3-2) 完成协调发布，
v1.2.3 转为更早的不可变回滚证据**。各组件继续保留独立、不可变的版本标识。

v1.2.3 最初是 v1.2.2 根镜像发布不完整后的同步前向修复。根仓库、可复用 Framework 和唯一的

`origin/main` 的精确提交发布，而不移动或重发其他组件：

| 组件 | 版本与标签 | 前置条件 |
| --- | --- | --- |
| Framework | `mss-boot/v1.2.3` | 完整 `GOWORK=off` 测试与 `pre-framework` 授权 |
| Admin V6 | `web/antd-v6/v1.2.3` | 集中前端门禁、便携制品、深链接交付和同提交镜像 |

## v1.2.2 不完整列车

v1.2.2 的公开状态必须保留为不可变审计事实：

- `mss-boot/v1.2.2`、`web/antd-v6/v1.2.2`、V6 Release、便携制品和 V6 镜像已从
  `29a99f2bdb9a2c516459529918795404c153df2e` 成功发布；
- 根 `v1.2.2` 标签、候选资格和六个平台 ZIP 预组装检查已完成；
- 根公开镜像构建在 QEMU 内编译 arm64 Go 二进制，单步耗时 2320 秒；
- 编译完成后刚进入镜像清单导出与推送，40 分钟作业上限即取消运行，因此根公开镜像和
  根 GitHub Release 均未完成。

禁止删除、移动、复用或补发上述标签与 Release。v1.2.3 从修复后、重新评审并合入
`main` 的新提交重新执行全部同步资格和发布。

## 完整修复范围

本次新增修复同时覆盖构建方式、时间预算和回归合同：

1. Dockerfile 的 Go builder 固定使用 BuildKit `BUILDPLATFORM`，不再在目标 arm64 容器内
   通过 QEMU 编译 Go。
2. `TARGETOS`、`TARGETARCH` 显式传给 `CGO_ENABLED=0` 的 Go 编译；最终运行层仍分别生成
   amd64/arm64，并保留 provenance 与 SBOM。
3. 根镜像 publish job 的有界上限从 40 分钟调整为 90 分钟，为清单导出、证明、缓存和
   GHCR 上传保留安全余量。
4. 静态合同测试要求上述原生交叉编译与最少 75 分钟上限，后续退回 QEMU 编译会在 PR
   阶段失败。

v1.2.3 同时继承并重新验证 v1.2.2 已完成的生成、上传和最终消费三层便携制品修复：

1. Admin `build:release` 与文档构建删除 Umi/Dumi 为动态参数生成的字面占位 HTML
   目录，例如 `:id` 和 `:provider`。只有内容恰好为一个 `index.html` 的占位目录可删除；
   出现其他内容立即失败。
2. 生成后的所有目录统一为 `0755`，静态文件统一为 `0644`，避免限制性 `umask` 让
   Nginx worker 返回 403。
3. 通用检查器验证真实目录以及 ZIP/TAR 成员，拒绝 Windows 非法字符、控制字符、路径
   穿越、尾随空格/点、设备保留名、大小写冲突、链接和超长组件。
4. 独立 V6 与根工作流都只上传 `dist-v6.tar.gz`、`FRONTEND-V6-BUILD-INFO` 和
   `SHA256SUMS.frontend-v6`，不再上传原始 `dist`。
5. 根组装先校验 checksum，再解压并检查 `dist`，最后逐一检查 Linux、Darwin、Windows
   amd64/arm64 六个 ZIP 的成员名。
6. 浏览器失败证据、readiness 报告和后端 runtime 目录等剩余原始目录上传都有前置检查；
   静态治理测试会清点所有上传点，新出现的无保护目录将使 CI 失败。
7. production Nginx smoke 除固定路由、哈希资源、缓存和 404 外，还验证真实动态深链接
   `/departments/42` 在删除占位目录后仍返回 SPA。
8. Playwright 资格前端独占 `18001`、使用非持久编译缓存且禁止复用本地 `8001` 开发服务，
   避免测试登录与直连后端使用不同签名密钥或争用 `.turbopack` 锁而产生伪失败。

## 数据库、API 与兼容性

本补丁不新增数据库迁移，也不改变公共 Framework API。v1.2.0/v1.2.1/v1.2.2 的前向迁移、
HttpOnly/CSRF 浏览器会话、后端强制授权和 V6-only 边界保持不变。

从现有安装升级前必须备份数据库。迁移后仍需从 `admin` 执行一次实际路由同步：

```shell
STAGE=local go run . server -a
```

仅有 `/healthz` 或页面可访问不代表权限数据就绪；“权限管理 → 菜单管理 → 绑定 API”必须
出现非空可选 API。`admin/go.mod` 在发布提交上依赖 `mss-boot v1.2.3`，本地 workspace
replace 不能作为外部可解析证明。

## 资格门禁

结构化入口为 `.mss/features/foundation-v1-2-3-release.yaml`，资格清单只选择该 Feature；
v1.2.0、v1.2.1 和 v1.2.2 作为不完整列车证据显式 carry-forward。

1. checkpoint：Feature、策略、命令、release 工具测试、原生交叉编译合同、四个 tag namespace 和全仓上传清点。
2. feature-freeze：根与 Admin Go、Framework `GOWORK=off`、V6 集中门禁、限制性 umask
   构建、目录/TAR/ZIP 检查、production delivery smoke 和文档构建。
3. 精确 SHA 人工证据：内置浏览器、三数据库 fresh/upgrade/API 注册表、Blueprint 升级演练。
4. `pre-framework`：选择成功的独立 readiness run，授权 Framework 与 V6 写入。
5. 外部解析：仓库外、`GOWORK=off`、纯代理解析 `mss-boot@v1.2.3` 并记录 checksum。
6. `pre-root`：选择另一个成功 readiness run，授权根发行版和匹配 runtime image 写入。
7. 发布后：核对 tags、Releases、archives、archive members、checksums、images、安装、
   迁移、API 注册表和恢复。

任何实现或发布合同变更都会产生新候选提交，并使受影响的旧证据失效。

## 发布顺序

1. 通过 PR 合并修复，重新获取远端并确认 tracked worktree 干净。
2. 冻结完整 SHA，执行 feature-freeze，不授予发布权。
3. 完成同 SHA 浏览器、三数据库/API 注册表与 Blueprint 证据。
4. 执行并选择 `pre-framework` 权威 run。
5. 发布 `mss-boot/v1.2.3`，在外部临时模块验证纯代理解析。
6. 发布同 SHA 的 `web/antd-v6/v1.2.3`、便携制品和匹配镜像。
7. 执行并选择独立 `pre-root` 权威 run，发布根 runtime image 和 `v1.2.3` Release。
8. Docs 候选独立通过 PR 合并后，仅创建 `docs/v1.2.3`，由 Docs 工作流校验制品、部署
   Cloudflare、核对公开 `/release.json` 并发布 Docs GitHub Release；不重发前三个组件。
9. 下载所有公开资产，在仓库外重新校验 checksum、成员路径、运行身份和恢复合同。

某一步失败时立即停止后续组件。所有已创建标签保持原位，不能移动或复用。

## 回滚

部署失败时停止扩散，恢复升级前数据库备份，部署上一组已资格化的 V6 后端/前端，验证
登录、菜单、API 绑定、权限负例、会话与核心写入，并保留失败提交、日志摘要和证据链接。
禁止恢复 V5、移动标签、在已迁移生产库上临时 down migration 或绕过 readiness。
