# v1.3.2 发布、升级与回滚

> 历史版本：本页仅保留不可变发布、升级与恢复证据，不用于新项目。当前使用路径请从 [v1.3.5 快速开始](/getting-started) 进入。

`v1.3.2` 已从精确 merged-main 提交
`635fbb03a82976941e527d8ac1000fec0624abac` 完成全部资格验证、协调发布和公开对账，

## 为什么使用 v1.3.2

`mss-boot/v1.3.1` 已公开发布，但 `admin/v1.3.1` 在独立 Module 下载时发现提交的
Framework Sum 与最终公开树不一致；Admin Release 与后续组件均未完成。所有 v1.3.1
引用保持不可变，因此完整列车使用新的补丁版本，并在任何 Tag 创建前计算最终树的规范 Sum。

## 协调身份

| 组件 | 精确身份 |
| --- | --- |
| Root | `v1.3.2` |
| Framework | `mss-boot/v1.3.2` |
| Admin Go Module | `admin/v1.3.2` |
| Admin Web | `web/antd-v6/v1.3.2`、`@mss-boot-io/admin-web@1.3.2` |
| Docs | 初始协调标签 `docs/v1.3.2`；站点内容修订 `docs/v1.3.2+docs.1` |

所有身份均解析到同一个已合并 `main` 的完整 SHA。实际发布顺序为：feature-freeze、
pre-framework、Framework、Admin、Admin Web、pre-root、Root、Docs、官方 npm、只读对账。

`docs/v1.3.2` 保持不可变并继续证明最初协调发布。稳定版文档在该标签之后合入 `main` 时，
公开站点通过 `docs/v1.3.2+docs.N` 修订前向更新；修订号选择尚未使用的最小正整数。
Docs 修订不改变产品稳定版本，也不重新发布 Framework、Admin、Admin Web、Root、npm 或镜像。
本次站点对账使用 `docs/v1.3.2+docs.1`，并以公开 `/release.json`、GitHub Release、部署
校验和和浏览器可见内容作为完成证据。

## 校验和修复

发布门禁从最终提交中读取每个已跟踪的 `mss-boot/` 文件，生成不含 `replace` 的本地 Go
Proxy，并由当前 Go 工具链计算规范 Module Sum 和 GoMod Sum。两个值必须与
`admin/go.sum` 中唯一的 `v1.3.2` 记录完全一致。

该比较在 checkpoint、pre-framework、Framework Release 和 Admin Release 中重复执行。
未跟踪 Framework 文件、版本漂移、重复 Sum 或最终树变化都会失败关闭。Framework 公开后，
Admin 还必须以 `GOWORK=off` 从公共来源完成 download、test、vet、build 和外部消费者验证。

## 变更范围与兼容性

- 保留原子 Business Module 注册、受生命周期保护的 Admin 命令入口和 fail-closed 前端扩展边界。
- 发布策略、Blueprint、Thin Host 锁、Go 依赖和 npm 包统一到 v1.3.2。
- 新增最终 Framework 树与 Admin 元数据的可执行校验和一致性门禁。
- 本补丁没有数据库 Schema、HTTP API、认证、授权或迁移顺序变化。

## 安装

全部公开制品已经完成并对账，可以使用精确版本安装：

```shell
go get github.com/mss-boot-io/mss-boot-admin/mss-boot@v1.3.2
go get github.com/mss-boot-io/mss-boot-admin/admin@v1.3.2
corepack pnpm@10.34.5 add --save-exact @mss-boot-io/admin-web@1.3.2
```

Thin Host 必须同时更新 Admin、Framework、前端和 `.mss/lock.yaml`，不能混用 v1.3.1
或移动的 `latest` 标签。

## 升级步骤

1. 记录当前 Git SHA、Go Module、npm 包、镜像 digest、数据库版本和 API 注册表状态。
2. 创建并验证数据库备份；在隔离环境证明可以恢复。
3. 先生成升级计划，检查 Blueprint 管理文件与业务自有文件边界。
4. 在维护窗口运行现有向前迁移，再执行一次 `server -a` 同步 API 注册表。
5. 验证菜单绑定 API 非空、后端权限负例、登录与刷新、`/app-config`、`/suppliers`、刷新和 404。
6. 同时切换匹配的后端与前端，不混用不同版本。

```shell
go run ./cmd/mss --root ../orders-admin upgrade admin v1.3.2 \
  --foundation . \
  --format json

go run ./cmd/mss --root ../orders-admin upgrade admin v1.3.2 \
  --foundation . \
  --apply --yes \
  --format json
```

## 发布后 npm 安全状态

- npmjs 的 `latest` dist-tag 已指向 `@mss-boot-io/admin-web@1.3.2`；
- Trusted Publisher 使用 GitHub Actions，限定为 `mss-boot-io/mss-boot-admin`、
  `npm-release.yml`、`release-v6`，且只允许 `npm publish`；
- 一次性 npm bootstrap Token 已撤销，npm Token 列表为空；
- GitHub `release-v6` 环境中的 `NPM_TOKEN` Secret 已删除并验证不存在；
- 后续发布没有 Token 回退，OIDC 身份不匹配时失败关闭。

## 回滚

v1.2.3 是 v1.3.2 的上一稳定版与协调回滚基线。回滚必须同时恢复已验证的
数据库备份、匹配的 Root/Admin/Framework/Admin Web 制品、精确镜像 digest、Thin Host
锁，以及与数据对应的 API 注册表和权限投影。

不要临时编写 down migration，也不要移动任何 v1.3.1 或 v1.3.2 引用。公开后发现需要
源码修复时，使用新的补丁版本并重新执行受影响门禁。
