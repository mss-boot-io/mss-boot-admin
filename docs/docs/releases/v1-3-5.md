# v1.3.5 不可变部分发布记录

v1.3.5 从精确 merged-main 提交
`396f60615cdfa589353b16ef9d3531e249e65432` 发布了 Framework、Admin 与 Admin Web，
并由受保护 promotion 创建了精确 annotated Root Tag。promotion 随后因错误忽略 Git
标签消息的规范尾换行而失败，自然触发的 Root candidate 和 container 运行在公开前取消。
Root Release 与工具、Docs、官方 npmjs 包和后端镜像未发布。

:::warning
Root Tag 已被 Go Proxy 与 SumDB 观察，v1.3.5 因此不能删除、移动、重建、复用或补发。
本页是审计记录，不提供安装、创建、开发或升级命令。当前稳定版本仍是 v1.3.2；完整修复
需要尚未选择的未使用版本、全新的 merged-main 提交和重新资格。
:::

## Root 工具资产：未发布

原候选合同计划让 Root GitHub Release 为 Linux、macOS 与 Windows 的 amd64/arm64 提供：

- `mss-tools-v1.3.5-{linux|darwin}-{amd64|arm64}.tar.gz`；
- 对应 Windows ZIP；
- `install-mss.sh` 与 `install-mss.ps1`；
- `SHA256SUMS.tools-v1.3.5`；
- 来源、提交与构建证明。

这些名称只记录预期资产清单。资产没有公开，不能下载、自行构建、手工附加到既有 Tag，
也不能把 v1.3.2 工具冒充为 v1.3.5 工具。原设计要求归档只包含两个公共二进制、
`BUILD-INFO` 和 `LICENSE`，安装前核验摘要、版本与源提交；这些要求没有在 v1.3.5
形成可消费的发布结果。

## 原候选采用接口：未发布

原合同计划由同一 Root Release 提供安装、空目录应用创建、开发编排、完整验证和
Blueprint 三方升级。生成结果还应精确绑定同版本 Admin、Framework 与官方 npmjs 包，
并保留 Blueprint manifest、冻结锁、业务所有权接缝和 CI 合同。

由于 Root 工具和 npmjs 包均缺失，这些接口没有成为 v1.3.5 的公共产品面。本记录故意
不保留候选命令，避免“标注不可执行”的片段仍被复制为快速开始。初始管理员凭据、开发
地址与升级流程也不构成 v1.3.5 采用指引。

## 缺口与后续合规要求

这次停止说明，昂贵验证不能散落在不可变 Tag 创建之后。未来未使用版本必须：

- 先在 `main` 的精确提交上运行唯一 Root preview；preview 一次完成测试、依赖审计、浏览器、
  六平台工具与 Root 归档、Admin Web tarball，以及后端和前端双架构镜像资格，但不公开发布；
- Framework、Admin、Admin Web Tag 依次创建，正式工作流只核对身份、策略、同版本 preview
  和必要前置 Release，再执行不可避免的公开写入；
- 一个 Root Tag 并行触发 Root Release、后端镜像和官方 npmjs；三个工作流共享同一 preview，
  但互不等待，避免把一个发布面的波动扩散成整条列车失败；
- Docs 从后续文档 PR 的新 merged-main 提交独立发布，不阻塞包、镜像、工具或 npmjs；
- 从干净空目录和 preview 生成的精确工具及包开始外部使用方资格；
- 匿名解析公共 Go Module 与 npmjs，不依赖 Git checkout、Foundation 源码、本地 Go
  replacement、本地 npm tarball 或手写锁文件；
- 覆盖 Thin Host 后端和前端测试、构建、运行、权限正反例、业务扩展接缝与升级保留；
- 以公开标签、Release、包、镜像摘要和部署后的 Docs 做最终对账。

新的简化流程只能服务未来未使用版本，不能恢复或补发 v1.3.5。

## 发布顺序与失败闭锁

```text
merged main
  -> one Root preview (all expensive qualification, no publication)
  -> Framework Tag
  -> Admin Tag
  -> Admin Web Tag
  -> Root Tag
       |-> Root tools / GitHub Release
       |-> backend image
       `-> official npmjs
  -> later Docs PR / Docs Tag
  -> public reconciliation
```

preview 失败时不得创建任何正式 Tag。Tag 工作流不重复重验证，只做精确身份、preview、不可变
状态、必要发布和公开身份核对；需要代码或工作流修复时，通过后续 PR 合入 `main`，冻结新的
merged-main 提交并重新运行 preview，不允许用手工例外绕过失败门禁。

## 不可变恢复边界

- 已公开的 v1.3.5 标签、Release、包和镜像保持原样；
- 不移动 Tag、不重写 Release、不覆盖包版本或镜像 digest；
- 不把缺失资产补附到既有 Root Tag；
- 下游需要可执行稳定资料时返回 [v1.3.2 稳定记录](/releases/archive/v1-3-2)；
- 完整修复只能进入尚未选择的未使用版本。

[mss-shop](/getting-started/mss-shop) 不得从这个部分发布列车生成。它必须等待显式选择的
未使用完整版本及其公共工具和包，才能建立独立基线并成为通用单租户商城范本。
