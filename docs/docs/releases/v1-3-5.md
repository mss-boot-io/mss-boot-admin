# v1.3.5 发布、安装、升级与回滚

v1.3.5 是一次统一的协调补丁列车，用于把 Root 工具、Framework、Admin、Admin Web、
Docs、镜像与 npmjs 恢复为同一 merged-main 提交上的完整 package-first 发行。它承接
[v1.3.4 组件部分发布历史](/releases/archive/v1-3-4)，且不移动或覆盖任何旧 Tag、
Release、包版本或镜像摘要。

:::warning
当前源码描述的是 v1.3.5 候选合同，不等同于公开发行已经完成。只有 GitHub Release、
Go 代理、npmjs、镜像、Docs `/release.json` 和空目录使用方验证全部对账到同一精确
提交后，新项目和升级才能执行本页命令。在此之前，以发布策略声明的当前稳定版本为准。
:::

## 修复范围

v1.3.4 的 Root 前使用方门禁发现：生成 Thin Host 的前端锁文件没有保留候选 npm 元数据
中的 `dist.tarball`，pnpm frozen-lockfile 因而推导出无效 registry 地址。v1.3.5 在
发布任何新组件 Tag 前统一完成以下修复与资格验证：

- 候选 Admin Web 元数据同时保留版本、integrity 与 tarball URL；
- Thin Host 生成和升级锁文件都从同一候选 tarball 的真实元数据生成；
- checkout-free 使用方测试从空目录安装 Release 构建工具，并使用 `GOWORK=off`、
  无本地 `replace`、无本地 npm tarball 的依赖路径；
- Framework/Admin 候选继续复现 Go 子目录 Module 继承仓库根 `LICENSE` 的规范
  ZIP 与校验和语义；
- Root 工具、Docs、容器、npmjs 与 mss-shop 采用者范本都在完整公共对账之后继续。

本补丁不改变数据库 Schema、HTTP API、认证、授权或迁移顺序；它修复发行元数据和外部
使用方资格路径，并把所有周边工具与文档收敛到一个版本。

## Root 工具资产

Root GitHub Release 为 Linux、macOS、Windows 的 amd64/arm64 提供：

- `mss-tools-v1.3.5-{linux|darwin}-{amd64|arm64}.tar.gz`；
- 对应 Windows ZIP；
- `install-mss.sh` 与 `install-mss.ps1`；
- `SHA256SUMS.tools-v1.3.5`；
- 来源、提交与构建证明。

归档根目录只包含 `mss`、`mss-mcp`、`BUILD-INFO` 和 `LICENSE`。安装器先校验
摘要再替换目标文件，不使用 `sudo`、不修改 shell profile。两个二进制必须报告相同
版本、提交和构建时间。

## 安装与创建

确认公开对账完成后，Linux 或 macOS 使用：

```sh
curl -fsSLO https://github.com/mss-boot-io/mss-boot-admin/releases/download/v1.3.5/install-mss.sh
bash ./install-mss.sh --version v1.3.5 --install-dir "$HOME/.local/bin"
export PATH="$HOME/.local/bin:$PATH"
mss --version
mss-mcp --version
```

Windows PowerShell 使用：

```powershell
Invoke-WebRequest https://github.com/mss-boot-io/mss-boot-admin/releases/download/v1.3.5/install-mss.ps1 -OutFile install-mss.ps1
& .\install-mss.ps1 -Version v1.3.5 -InstallDir "$HOME\.local\bin"
$env:Path = "$HOME\.local\bin;$env:Path"
mss --version
mss-mcp --version
```

从空目录创建 Thin Host：

```sh
mss new app my-admin \
  --module github.com/example/my-admin \
  --destination ./my-admin \
  --write \
  --git-init
cd my-admin
mss doctor --strict
mss setup
mss dev
```

生成结果精确导入 `admin@v1.3.5`、`mss-boot@v1.3.5` 和
`@mss-boot-io/admin-web@1.3.5`，并保留 Blueprint manifest、锁文件、业务所有权
seam、验证入口和 CI 合同。普通采用者不需要 Foundation 源码目录。

第一次交互式 `mss setup` 通过隐藏提示读取初始管理员密码；非交互环境只在 setup
进程中注入一次性 `MSS_ADMIN_INITIAL_PASSWORD`。密码不得进入命令参数、报告、生成
文件或长期服务环境。初始用户名为 `admin`，Admin Web 地址为
`http://127.0.0.1:8001`，系统没有默认密码。

完整前置条件、开发命令和故障排查见[快速开始](/getting-started)、
[工具说明](/getting-started/tooling)和[包与导入边界](/getting-started/packages)。

## 升级

先安装目标 v1.3.5 工具，确认 `mss --version` 与 `mss-mcp --version` 同源，并备份
代码、配置、数据库和业务数据。只有保留 `.mss/blueprint-manifest.json` 的 Blueprint
Thin Host 才能使用三方升级；手工拼装或丢失 manifest 的仓库必须先在新目录生成目标
版本基线，再迁入业务所有文件。

```sh
mss upgrade admin v1.3.5
mss upgrade admin v1.3.5 --apply --yes
mss doctor --strict
mss verify --all
mss upgrade admin v1.3.5
```

第一次计划只读；应用只更新受管文件并保留业务和未知文件；快照最后写入。第二次计划
必须没有 create、update、delete 或 conflict。数据库变化仍需独立备份、迁移和恢复演练。

## 发布顺序与资格

```text
merged main
  -> Framework
  -> Admin
  -> Admin Web candidate / image / GitHub Release
  -> protected Root tag promotion
  -> Root tools / image / GitHub Release
  -> Docs
  -> official npmjs
  -> public reconciliation
```

每个阶段都重新验证精确提交和全部前置证据。最终使用方资格从空目录和 Release 构建
工具开始，不允许 Git checkout、Foundation 源码、本地 Go replacement、本地 npm
tarball 或手写锁文件，并覆盖：

1. 工具摘要、版本、提交和归档边界；
2. 公共 Go Module 与 npmjs 匿名解析；
3. `doctor --strict`、`setup`、`dev`、`verify --all`；
4. Thin Host 后端与前端测试、构建和运行；
5. 手写模块、权限、路由、本地化与业务 seam 的升级保留；
6. 匿名 401、受限用户 403、授权 root 200 和内置浏览器关键流程；
7. Admin core 与业务 UI/server 路径冲突失败关闭。

## 回滚与修复

- 发布前缺陷：通过后续 PR 修复，选择新的 merged-main 提交并重跑受影响阶段；
- 发布后缺陷：保持 v1.3.5 ref 与资产不变，通过新的补丁列车修复；
- 下游回退：恢复匹配版本的代码、配置、锁、数据库快照和业务数据；
- 禁止移动 Tag、重写 Release、覆盖 npm 版本或替换镜像 digest。

完整公开对账完成后，[mss-shop](/getting-started/mss-shop) 才从 v1.3.5 公共工具和包
生成独立基线，作为通用单租户商城管理系统的 package-first 采用者范本。
