# v1.3.7 发布候选说明

:::warning
v1.3.7 是新的 complete package-first release candidate，**尚未发布、不可安装、不可创建
或升级应用，也不是稳定版**。v1.3.2 仍是当前唯一协调稳定版；v1.3.5 与 v1.3.6 都是
不可续的不可变部分发布列车。
:::

v1.3.7 必须从修复 PR 合并后的一个全新、干净、精确 `origin/main` 提交开始。它不移动、
删除、复用或补全任何 v1.3.6 身份。正式 Tag 之前，要用同一提交完成一次非发布 Root
preview，并核对预期制品清单与浏览器验收。

## 本轮必须修复的两个门禁

### 显式 Root image preview

- `container.yml` 的 `workflow_call` 声明必填布尔 `release_preview`；
- `release.yml` 调用时显式传入 `release_preview: true` 与精确版本；
- 授权、构建信息、多架构构建、OCI 校验、暂存和 artifact 上传全部依赖该输入；
- 合同测试拒绝再用 `github.event_name == 'workflow_call'` 推断被调用模式；
- preview 结束时必须看到并验证 Root image artifact，不能只依赖 workflow 绿色状态。

### 无令牌 npm Trusted Publishing

npm package 的 Trusted Publisher 必须精确配置为：

| 字段 | 值 |
| --- | --- |
| Package | `@mss-boot-io/admin-web` |
| Organization/User | `mss-boot-io` |
| Repository | `mss-boot-admin` |
| Workflow filename | `npm-release.yml` |
| Environment | `npm-auto` |

workflow 保留 `id-token: write` 和 `npm publish --provenance`，发布进程继续清除
`NPM_TOKEN` 与 `NODE_AUTH_TOKEN`。Trusted Publisher 的 live 配置必须在第一个正式 Tag
之前验证；不允许用长期 token 绕过不匹配。

## 资格与发布顺序

1. 修复和候选合同经 PR 审核并合并到 `main`；
2. 冻结 exact merged-main commit，复查 v1.3.7 远端身份为空；
3. 运行一次非发布 Root preview，完成 Go、前端、Docs、迁移、安全、外部 Thin Host、
   Root OCI、浏览器与回退验收；
4. 核对 npm Trusted Publisher live 身份和 GitHub `npm-auto` environment；
5. 由 `lwnmengjing` 依次创建 Framework、Admin、Admin Web、Root annotated tags；
6. 分别对账 Root Release、工具、Root image、前端 image 和官方 npmjs；
7. package/image 列车完整后，使用独立 `docs/v1.3.7` Tag 发布并核对生产
   `/release.json`、页面、控制台和失败请求；
8. 全部完成后，才通过另一个 PR 讨论把 stable 从 v1.3.2 推进到 v1.3.7。

## 安全、迁移与回退边界

- 演示配置仍是编译能力之上的严格 data-only 稀疏覆盖，不能携带脚本、HTML、SQL、URL、
  权限、路由、动态 import 或可执行组件；后端 RBAC 始终是最终权威。
- 数据库迁移保持向前兼容。部署顺序仍是 migrate、一次 `server -a` 同步，再启动长期
  server；普通回退不执行破坏性 down migration。
- 初始化管理员密码只允许隐藏交互输入或单进程 `MSS_ADMIN_INITIAL_PASSWORD`，不得写入
  镜像、配置、日志或发布制品。
- 发布前和发布后的正常回退基线都是完整匹配的 v1.3.2 Admin、Framework、前端、配置与
  冻结锁，并保留可向前兼容的实时数据库。数据库备份恢复只属于有损灾难恢复。

## 完成定义

只有 Root、Framework、Admin、Admin Web、官方 npmjs、Root/前端 images、工具、校验和、
provenance、Docs、Go Proxy、安装器和仓库外 Thin Host 都解析到同一 v1.3.7 与精确提交，
且真实浏览器验收无控制台错误和失败请求，候选才具备稳定版评估资格。在此之前，
[v1.3.2 稳定记录](/releases/archive/v1-3-2) 仍是唯一采用基线，
[v1.3.6 记录](/releases/v1-3-6) 仅供不可变审计。
