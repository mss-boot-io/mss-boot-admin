# v1.3.1 发布、升级与回滚

:::warning
`v1.3.1` 是当前唯一活动的稳定版候选。它必须从 PR 合并后的一个精确 `main`
提交完成全部资格验证后才能发布。当前已对账稳定版仍是 `v1.2.3`。
:::

## 为什么使用 v1.3.1

`mss-boot/v1.3.0` 已从旧提交公开发布，但 `admin/v1.3.0` 因缺少 Framework
校验和而在独立 Module 测试阶段失败；Root、Admin Web、Docs 和 npmjs 稳定制品没有完成。
这些引用和失败记录保持不可变，不能删除、移动或复用，因此完整列车使用新的补丁版本。

## 协调身份

| 组件 | 精确身份 |
| --- | --- |
| Root | `v1.3.1` |
| Framework | `mss-boot/v1.3.1` |
| Admin Go Module | `admin/v1.3.1` |
| Admin Web | `web/antd-v6/v1.3.1`、`@mss-boot-io/admin-web@1.3.1` |
| Docs | `docs/v1.3.1` |

所有身份必须解析到同一个已合并 `main` 的完整 SHA。发布顺序固定为：feature-freeze、
pre-framework、Framework、Admin、Admin Web、pre-root、Root、Docs、官方 npm、只读对账。

## 变更范围

- Business Module 注册改为原子提交；失败注册不会泄漏描述、路由或迁移。
- Admin 命令执行只通过受生命周期保护的公开入口。
- Admin Web 只允许增加 `businessRoutes`，不能替换核心路由、冲突检查或 403/404 兜底。
- Admin Module 在发布前携带精确 `mss-boot/v1.3.1` Module 与 `go.mod` 校验和。
- 发布策略、Blueprint、Thin Host 锁和官方 npm 最后发布路径统一到 v1.3.1。

本版本没有数据库 Schema、HTTP API、认证、授权或迁移顺序变化。Go
`Application.Command` 及旧公开命令构造签名仅保留为 Deprecated 的失败关闭兼容桩，
不会返回真实 Admin 命令树；前端 `routes` 选项属于未完成稳定发布的不安全扩展逃逸口。
使用方应改为 `ExecuteContext` / `ExecuteArgsContext` 和 `businessRoutes`。

## 安装

只有在全部公开制品完成并对账后才执行：

```shell
go get github.com/mss-boot-io/mss-boot-admin/mss-boot@v1.3.1
go get github.com/mss-boot-io/mss-boot-admin/admin@v1.3.1
corepack pnpm@10.34.5 add --save-exact @mss-boot-io/admin-web@1.3.1
```

Thin Host 必须同时更新后端、Framework、前端和 `.mss/lock.yaml`，不能混用 v1.3.0
或移动的 `latest` 标签。

## 升级步骤

1. 记录当前 Git SHA、Go Module、npm 包、镜像 digest、数据库版本和 API 注册表状态。
2. 创建并验证数据库备份；在隔离环境证明可以恢复。
3. 先生成升级计划，检查 Blueprint 管理文件与业务自有文件边界。
4. 在维护窗口运行现有向前迁移，再执行一次 `server -a` 同步 API 注册表。
5. 验证菜单绑定 API 非空、后端权限负例、登录与刷新、`/app-config`、`/suppliers`、刷新和 404。
6. 同时切换匹配的后端与前端，不混用不同版本。

```shell
go run ./cmd/mss --root ../orders-admin upgrade admin v1.3.1 \
  --foundation . \
  --format json

go run ./cmd/mss --root ../orders-admin upgrade admin v1.3.1 \
  --foundation . \
  --apply --yes \
  --format json
```

## 发布前门禁

- `go run ./cmd/mss doctor --strict`
- `go run ./cmd/mss verify --all`
- `go run ./cmd/mss eval run --all`
- Admin 与 Framework 的 `GOWORK=off` 测试、vet 和外部消费者
- Admin Web lint、测试、构建、包、Playwright 与便携路径验证
- Docs 构建和 Codex 内置浏览器桌面/窄屏证据
- SQLite、MySQL、PostgreSQL 的新装与升级路径
- 所有 v1.3.1 Tag 在首次发布前不存在，发布后全部解析到同一个冻结 SHA

## 回滚

在 v1.3.1 完成公开对账前，协调回滚基线仍是 v1.2.3。回滚必须同时恢复：

- 已验证的 v1.2.3 数据库备份；
- 匹配的 Root、Admin、Framework 与 Admin Web 制品；
- 精确镜像 digest 和 Thin Host 锁；
- 与恢复数据对应的 API 注册表和权限投影。

不要临时编写 down migration，也不要移动任何 v1.3.0 或 v1.3.1 引用。公开后发现需要
源码修复时，使用新的补丁版本并重新执行受影响门禁。
